# Імітаційна модель роботизованої ГВС (варіант B20)

Імітаційна модель експериментальної роботизованої гнучкої виробничої системи на основі формального
опису **мережею масового обслуговування** (формалізм методичних рекомендацій: СМО з пристроями
у станах «вільний», «зайнятий», «блокований», блокування маршрутів B(S, t)). Алгоритм імітації власний
(подійний, з просуванням часу до найближчої події), без спеціалізованих бібліотек імітації.

## Запуск

```bash
uv sync
uv run pytest            # тести
uv run fms --help        # перелік команд
```

| Команда | Що робить | Результат у `results/` |
|---|---|---|
| `uv run fms run` | один прогін, усі вихідні змінні | — (консоль) |
| `uv run fms trace --until 600` | протокол подій (для додатку А) | `trace_<strategy>.txt` |
| `uv run fms verify` | таблиця верифікації (варіювання вхідних змінних) | `verification.csv` |
| `uv run fms warmup --arrival 60` | перехідний період за умовою (4.1) записки, 5 прогонів | `warmup_series_a40.csv`, `warmup_summary_a40.csv` |
| `uv run fms reps --arrival 60` | кількість прогонів p = 20(σ/ε)², формула (2.11) записки | `replications_a40.csv` |
| `uv run fms compare --arrival 60` | порівняння способів закріплення роботів + ANOVA | `compare_a40_*.csv` |
| `uv run fms capacity` | пропускна здатність залежно від інтервалу надходження | `capacity*.csv` |
| `uv run fms dist --arrival 60 --max-n 500` | розподіл часу проходження, критерій χ² | `dist_*_<strategy>_a60.*` |
| `uv run fms improve` | пробні запуски пропозицій: 4 місця на M2, 4-й робот | `improvement_a40.csv` |
| `uv run fms plot-dist --tag nearest_a60 --top 3` | графік гістограми з кривими найкращих законів за результатами `dist` | `dist_hist_*.png` |
| `uv run fms plots` | усі рисунки для записки за збереженими результатами | `figures/fig_*.png` |

Спільні параметри: `--strategy dedicated|nearest` (якщо не задано — обидва варіанти),
`--arrival` (середній інтервал, с), `--t-end`, `--warmup`, `--reps`, `--seed`, `--jobs`.
Імена файлів результатів містять інтервал надходження, напр. `a40`, тому прогони з різним
`--arrival` не перезаписують один одного.

## Команда `fms run`

Виконує **один прогін** моделі для кожного обраного способу закріплення роботів і друкує всі
вихідні змінні в консоль.

```bash
uv run fms run                                          # обидва варіанти, базові параметри
uv run fms run --strategy nearest                       # лише варіант 2
uv run fms run --arrival 60 --t-end 500000 --seed 7     # інший інтервал надходження, довший прогін
```

### Параметри запуску

| Параметр | Значення за замовчуванням | Що означає |
|---|---|---|
| `--strategy` | обидві | Спосіб закріплення роботів. `dedicated` — варіант 1: кожен робот обслуговує лише свій шлях (робот 1: A→M1, робот 2: M1→M2, робот 3: M2→W). `nearest` — варіант 2: будь-який робот на будь-якому шляху, призначається найближчий вільний. Якщо параметр не задано, прогін виконується для обох. |
| `--arrival` | `40` | Середній інтервал між надходженнями деталей, с (закон експоненціальний). 40 с = 90 дет./год. Більше значення — менше навантаження. |
| `--t-end` | `200000` | Час моделювання Tmod, с (200 000 с ≈ 55,6 год модельного часу). |
| `--warmup` | `30000` | Тривалість перехідного періоду, с. У цей момент уся статистика обнуляється, і вихідні змінні рахуються лише на інтервалі [warmup; t-end]. Стан системи (деталі, роботи) при цьому не змінюється. `0` — рахувати з початку. |
| `--seed` | `1` | Зерно генераторів випадкових чисел. Однакове зерно дає однаковий результат (відтворюваність); різні зерна — незалежні прогони. |
| `--reps`, `--jobs`, `--out` | — | Для `run` не використовуються (потрібні іншим командам: кількість прогонів, кількість паралельних процесів, каталог результатів). |

Решта вхідних змінних (часи обробки, захоплення, переїздів, кількість місць) задається в
[src/fms/params.py](src/fms/params.py) і за замовчуванням відповідає умові завдання:
M1 — norm(60, 10), M2 — exp(100), захоплення/вивільнення — unif(8, 1) = 8±1 с, по 3 місця на верстатах,
3 роботи, переїзди A–M1 = 6, M1–M2 = 7, M2–W = 5 с.

### Вихідні змінні

Усі значення, крім службових, рахуються за період після перехідного: T = t-end − warmup.

**Службові**

| Змінна | Що означає |
|---|---|
| `strategy`, `seed` | Параметри цього прогону. |
| `t_end` | Момент закінчення моделювання, с. |
| `t_warmup` | Момент обнулення статистики (кінець перехідного періоду), с. |

**Потоки деталей**

| Змінна | Що означає |
|---|---|
| `arrived` | Скільки деталей надійшло на пункт прибуття за період T. |
| `completed` | Скільки деталей доставлено на склад за період T. |
| `wip_end` | Скільки деталей перебуває в системі в кінці прогону (на площадці прибуття, на верстатах, у роботів). Якщо велике і зростає з t-end — режим нестійкий. |
| `throughput_per_hour` | **Пропускна здатність**: деталей на склад за годину = completed / T · 3600. Головний критерій порівняння варіантів. У стійкому режимі ≈ 3600 / arrival. |

**Час проходження деталі** (від надходження на пункт прибуття до завершення вивільнення на складі; по деталях, доставлених за період T), с

| Змінна | Що означає |
|---|---|
| `sojourn_mean`, `sojourn_std` | Середнє і стандартне відхилення. |
| `sojourn_min`, `sojourn_max` | Найменше і найбільше значення. |
| `sojourn_p50`, `sojourn_p90`, `sojourn_p95` | Медіана, 90%- і 95%-квантилі: 90% деталей проходять систему не довше за `sojourn_p90`. |
| `wait_route1_mean` | Середнє очікування робота на пункті прибуття: від надходження деталі до початку її захоплення. |
| `wait_route2_mean` | Середнє очікування робота на M1: від завершення обробки до початку захоплення (весь цей час пристрій M1 блокований). |
| `wait_route3_mean` | Те саме для M2. |

**Місце зберігання на ділянці прибуття** (деталь займає пристрій СМО A від надходження до завершення її захоплення роботом)

| Змінна | Що означає |
|---|---|
| `buffer_max` | **Максимальна кількість деталей** L_max, що одночасно перебували на площадці, — шукана максимальна місткість. |
| `buffer_mean` | Середня кількість деталей, зважена за часом: Σ L·Δt / T. |
| `buffer_end` | Кількість деталей на площадці в кінці прогону. |
| `buffer_q95`, `buffer_q99` | Місткість, якої вистачає у 95% / 99% часу (за розподілом кількості деталей на площадці). |

**Верстати** (`M1_…`, `M2_…`): частки часу, усереднені за трьома пристроями (місцями) верстата, від 0 до 1

| Змінна | Що означає |
|---|---|
| `M*_occupied` | **Коефіцієнт використання верстата**: частка часу, коли пристрій не вільний (обробка, блокування, захоплення/вивільнення). |
| `M*_processing` | Частка часу, коли на місці йде власне обробка. |
| `M*_blocked` | Частка часу, коли пристрій блокований: оброблена деталь чекає робота (маршрут виходу закритий). |
| `M*_handling` | Частка часу, коли робот вивільняє деталь на місце або захоплює її з місця (затримка звільнення). |
| `M*_robot_waiting` | Частка часу, коли біля верстата стоїть робот із деталлю і чекає вільного місця (на весь верстат, а не на одне місце). |

`occupied = processing + blocked + handling`.

**Роботи** (`robot1_…`, `robot2_…`, `robot3_…`): частки часу від 0 до 1, за станами пристроїв робота

| Змінна | Що означає |
|---|---|
| `robotK_util` | **Коефіцієнт використання робота**: частка часу, коли він не вільний. |
| `robotK_empty_move` | Холостий хід: у варіанті 1 — повернення до точки завантаження свого шляху після вивільнення деталі, у варіанті 2 — переїзд до точки, де треба забрати деталь (СМО Х). |
| `robotK_grab` | Захоплення деталі. |
| `robotK_loaded_move` | Переїзд з деталлю. |
| `robotK_wait_slot` | Блокування: робот тримає деталь, поки на верстаті звільниться місце. |
| `robotK_release` | Вивільнення деталі. |
| `robotK_jobs_route1/2/3` | Скільки перевезень робот виконав на шляхах A→M1, M1→M2, M2→W за період T. У варіанті 1 ненульове лише для «свого» шляху. |
| `robots_util_mean` | Середній коефіцієнт використання роботів. |
| `empty_route1/2/3_mean` | Середній холостий хід робота, с, на одне перевезення шляху A→M1, M1→M2, M2→W. У варіанті 1 це повернення своїм шляхом: 6, 7, 5 с. |

`robotK_util = empty_move + grab + loaded_move + wait_slot + release`.

## Структура

```
src/fms/
  rng.py        генератори: exp = −m·ln ζ, unif(d,s), norm – полярний метод Марсальї; окремі потоки
  params.py     вхідні змінні та параметри
  elements.py   елементи мережі МО: Create (надходження), QS (СМО з пристроями Channel, стани 0/1/2,
                затримка звільнення), Route (дуга з блокуванням B(S, t)), Exit (вихід), Part, Robot
  model.py      склад мережі обох варіантів, предикати блокування, керування роботами,
                алгоритм імітації (календар подій), збір статистики
  cli.py        командний інтерфейс
  report_plots.py  рисунки для пояснювальної записки
  experiments/  verification, warmup, replications, compare, capacity, distribution, improvement
tests/          перевірки коректності алгоритму
```

## Відповідність формалізму

Запит мережі — деталь. Кожне місце, де може перебувати деталь, — пристрій СМО зі станом K:
0 — вільний, 1 — зайнятий, 2 — блокований. Деталь, що чекає на робота або на вільне місце, займає
блокований пристрій (черг між СМО немає). Подій дві: надходження деталі ззовні і завершення
обслуговування в пристрої; кінець затримки звільнення — теж завершення обслуговування, лише в пристрої
вже немає запиту.

| Об'єкт системи | Елемент мережі МО |
|---|---|
| надходження деталей exp(40) | зовнішнє надходження `Create` |
| площадка прибуття A | СМО A з необмеженою кількістю пристроїв; t = 0, затримка звільнення t_зх (місце зайняте до кінця захоплення) |
| верстат M1 / M2 (3 місця) | СМО з 3 пристроями без черги; t = t_вив + обробка, затримка звільнення t_зх |
| роботи, варіант 1 | три одноканальні СМО R1–R3; t = t_зх + d_S, затримка звільнення t_вив + d_S (вивільнення і повернення) |
| роботи, варіант 2 | триканальна СМО T1–T3 на кожному шляху (пристрій r — робот r); t = t_зх + d_S, затримка звільнення t_вив; положення роботів відстежує фрагмент П ⇄ Х (запити — роботи, холостий хід t = d(pos_r, src_S)) |
| склад W | СМО W з необмеженою кількістю пристроїв, t = t_вив; далі `Exit` |
| «немає вільного робота», «на верстаті немає місця» | блокування маршрутів B0–B4 через стан пристроїв (формули (2.1), (2.3) записки) і керування роботами К (формули (2.4), (2.5)) |

Тривалість захоплення або вивільнення h генерується в момент переходу деталі між пристроями і входить
одночасно в час обслуговування пристрою-приймача і в затримку звільнення пристрою-джерела.

## Припущення моделі

1. Пункти розташовані на лінії A – M1 – M2 – W; відстані A–M2 = 13, M1–W = 12, A–W = 18 с.
2. Варіант 1: робот після вивільнення деталі одразу повертається порожнім до точки завантаження свого
   шляху. Варіант 2: робот залишається в точці вивантаження і їде порожнім, коли його призначають.
3. Варіант 2: обирається пара (вільний робот, шлях) з найменшим холостим ходом; при рівності — випадково.
4. Місце на верстаті займається лише при вивільненні деталі; робот з деталлю чекає біля заповненого
   верстата (його пристрій блокований). У варіанті 2 робот не бере деталь для верстата, до якого вже
   везуть деталі на одного робота більше, ніж там вільних місць (D_S, формула (2.2) записки). Без цього
   правила роботи потрапляють у взаємне блокування; у варіанті 1 воно виконується завжди, бо до верстата
   їздить лише один робот.
5. Час обробки на M1 – усічений нормальний закон (значення ≤ 0 відкидаються).
6. Одночасні події виконуються у випадковому порядку; завершення обслуговування – раніше за надходження.


Умови експериментів обрано за результатами `fms warmup` і `fms reps`:

- **exp(40)** (умова завдання, система перевантажена): умова (4.1) з ε = 5 % для відгуків, що
  стабілізуються (пропускна здатність, завантаження M2 і роботів), виконується з T ≤ 58 000 с.
  Тому Tmod = 300 000 с, статистика збирається після 60 000 с. Час проходження і черга на площадці
  при exp(40) не стабілізуються (ростуть з часом моделювання).
- **exp(60)** (стійкий режим, для розподілу часу проходження і місткості площадки): для часу
  проходження умова (4.1) з ε = 5 % виконується лише з T ≈ 605 000 с у варіанті 1 і
  1 480 000 с у варіанті 2, тому Tmod = 1 500 000 с, статистика після 50 000 с.
- Кількість прогонів за (2.11) з ε = 2 %: 1–5 для пропускної здатності і коефіцієнтів використання,
  при exp(60) 9 і 27 для часу проходження (варіанти 1 і 2). Для максимальної кількості деталей
  на площадці відносна точність 2 % недосяжна, тому для неї точність задано абсолютною: 1–2 деталі.
  Порівняння варіантів виконано на 30 прогонах.

```bash
uv run fms trace --until 600
uv run fms verify
uv run fms warmup --arrival 40
uv run fms warmup --arrival 60 --t-end 1500000 --step 5000
uv run fms reps --arrival 40 --t-end 300000 --warmup 60000
uv run fms reps --arrival 60 --t-end 1500000 --warmup 50000
uv run fms compare --arrival 40 --reps 30 --t-end 300000 --warmup 60000
uv run fms compare --arrival 60 --reps 30 --t-end 1500000 --warmup 50000
uv run fms capacity --reps 10 --t-end 300000 --warmup 60000
uv run fms dist --arrival 60 --reps 20 --t-end 1500000 --warmup 50000 --max-n 500 --bins 12
uv run fms improve --reps 20 --t-end 300000 --warmup 60000
uv run fms plots
```
