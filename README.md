# Імітаційна модель роботизованої ГВС (варіант B20)

Імітаційна модель експериментальної роботизованої гнучкої виробничої системи на основі формального
опису **мережею масового обслуговування**. Алгоритм імітації власний (подійний, з просуванням часу
до найближчої події), без спеціалізованих бібліотек імітації.

## Запуск

```bash
uv sync
uv run pytest            # тести
uv run fms --help        # перелік команд
```

| Команда | Що робить | Результат у `results/` |
|---|---|---|
| `fms run` | один прогін, усі вихідні змінні | — (консоль) |
| `fms trace --until 600` | протокол подій (для додатку) | `trace_<strategy>.txt` |
| `fms verify` | таблиця верифікації (варіювання вхідних змінних) | `verification.csv` |
| `fms warmup [--arrival 60]` | перехідний період за формулою (3.1), ≥4 прогони | `warmup_series_a40.csv`, `warmup_summary_a40.csv` |
| `fms reps [--arrival 60]` | кількість прогонів p = 20(σ/ε)² (і за ЦГТ) | `replications_a40.csv` |
| `fms compare [--arrival 60]` | порівняння способів закріплення роботів + ANOVA | `compare_a40_*.csv` |
| `fms capacity` | пропускна здатність залежно від інтервалу надходження | `capacity*.csv` |
| `fms dist --arrival 60 --max-n 500` | розподіл часу проходження, критерій χ² | `dist_*_<strategy>_a60.*` |
| `fms improve` | пробні запуски пропозицій: 4 місця на M2, 4-й робот | `improvement_a40.csv` |
| `fms plot-dist [--tag nearest_a60] [--top 3]` | графік гістограми з кривими найкращих законів за результатами `dist` | `dist_hist_*.png` |
| `fms plots` | усі рисунки для записки за збереженими результатами | `figures/fig_*.png` |

Спільні параметри: `--strategy dedicated|nearest` (якщо не задано — обидва варіанти),
`--arrival` (середній інтервал, с), `--t-end`, `--warmup`, `--reps`, `--seed`, `--jobs`.
Імена файлів результатів містять інтервал надходження, напр. `a40`, тому прогони з різним
`--arrival` не перезаписують один одного.

## Команда `fms run`

Виконує **один прогін** моделі для кожного обраного способу закріплення роботів і друкує всі
вихідні змінні в консоль.

```bash
uv run fms run                                          # обидва варіанти, базові параметри
uv run fms run --strategy nearest                       # лише варіант 2
uv run fms run --arrival 60 --t-end 500000 --seed 7     # інший інтервал надходження, довший прогін
```

### Параметри запуску

| Параметр | Значення за замовчуванням | Що означає |
|---|---|---|
| `--strategy` | обидві | Спосіб закріплення роботів. `dedicated` — варіант 1: кожен робот обслуговує лише свій шлях (робот 1: A→M1, робот 2: M1→M2, робот 3: M2→W). `nearest` — варіант 2: будь-який робот на будь-якому шляху, призначається найближчий вільний. Якщо параметр не задано, прогін виконується для обох. |
| `--arrival` | `40` | Середній інтервал між надходженнями деталей, с (закон експоненціальний). 40 с = 90 дет./год. Більше значення — менше навантаження. |
| `--t-end` | `200000` | Час моделювання Tmod, с (200 000 с ≈ 55,6 год модельного часу). |
| `--warmup` | `30000` | Тривалість перехідного періоду, с. У цей момент уся статистика обнуляється, і вихідні змінні рахуються лише на інтервалі [warmup; t-end]. Стан системи (деталі, роботи) при цьому не змінюється. `0` — рахувати з початку. |
| `--seed` | `1` | Зерно генераторів випадкових чисел. Однакове зерно дає однаковий результат (відтворюваність); різні зерна — незалежні прогони. |
| `--reps`, `--jobs`, `--out` | — | Для `run` не використовуються (потрібні іншим командам: кількість прогонів, кількість паралельних процесів, каталог результатів). |

Решта вхідних змінних (часи обробки, захоплення, переїздів, кількість місць) задається в
[src/fms/params.py](src/fms/params.py) і за замовчуванням відповідає умові завдання:
M1 — norm(60, 10), M2 — exp(100), захоплення/вивільнення — unif(8, 1) = 8±1 с, по 3 місця на верстатах,
3 роботи, переїзди A–M1 = 6, M1–M2 = 7, M2–W = 5 с.

### Вихідні змінні

Усі значення, крім службових, рахуються за період після перехідного: T = t-end − warmup.

**Службові**

| Змінна | Що означає |
|---|---|
| `strategy`, `seed` | Параметри цього прогону. |
| `t_end` | Момент закінчення моделювання, с. |
| `t_warmup` | Момент обнулення статистики (кінець перехідного періоду), с. |

**Потоки деталей**

| Змінна | Що означає |
|---|---|
| `arrived` | Скільки деталей надійшло на пункт прибуття за період T. |
| `completed` | Скільки деталей доставлено на склад за період T. |
| `wip_end` | Скільки деталей перебуває в системі в кінці прогону (на площадці прибуття, на верстатах, у роботів). Якщо велике і зростає з t-end — режим нестійкий. |
| `throughput_per_hour` | **Пропускна здатність**: деталей на склад за годину = completed / T · 3600. Головний критерій порівняння варіантів. У стійкому режимі ≈ 3600 / arrival. |

**Час проходження деталі** (від надходження на пункт прибуття до завершення вивільнення на складі; по деталях, доставлених за період T), с

| Змінна | Що означає |
|---|---|
| `sojourn_mean`, `sojourn_std` | Середнє і стандартне відхилення. |
| `sojourn_min`, `sojourn_max` | Найменше і найбільше значення. |
| `sojourn_p50`, `sojourn_p90`, `sojourn_p95` | Медіана, 90%- і 95%-квантилі: 90% деталей проходять систему не довше за `sojourn_p90`. |
| `wait_route1_mean` | Середнє очікування робота на пункті прибуття: від надходження деталі до початку її захоплення. |
| `wait_route2_mean` | Середнє очікування робота на M1: від завершення обробки до початку захоплення (весь цей час місце на M1 заблоковане). |
| `wait_route3_mean` | Те саме для M2. |

**Місце зберігання на ділянці прибуття** (деталь перебуває тут від надходження до завершення її захоплення роботом)

| Змінна | Що означає |
|---|---|
| `buffer_max` | **Максимальна кількість деталей**, що одночасно перебували на площадці, — шукана максимальна місткість. |
| `buffer_mean` | Середня кількість деталей, зважена за часом: Σ L·Δt / T. |
| `buffer_end` | Кількість деталей на площадці в кінці прогону. |
| `buffer_q95`, `buffer_q99` | Місткість, якої вистачає у 95% / 99% часу (за розподілом кількості деталей на площадці). |

**Верстати** (`M1_…`, `M2_…`): частки часу, усереднені за трьома місцями верстата, від 0 до 1

| Змінна | Що означає |
|---|---|
| `M*_occupied` | **Коефіцієнт використання верстата**: частка часу, коли місце не вільне (обробка, блокування, захоплення/вивільнення). |
| `M*_processing` | Частка часу, коли на місці йде власне обробка. |
| `M*_blocked` | Частка часу, коли оброблена деталь лежить на місці і чекає робота (маршрут виходу заблокований). |
| `M*_handling` | Частка часу, коли робот вивільняє деталь на місце або захоплює її з місця. |
| `M*_robot_waiting` | Частка часу, коли біля верстата стоїть робот із деталлю і чекає вільного місця (на весь верстат, а не на одне місце). |

`occupied = processing + blocked + handling`.

**Роботи** (`robot1_…`, `robot2_…`, `robot3_…`): частки часу від 0 до 1

| Змінна | Що означає |
|---|---|
| `robotK_util` | **Коефіцієнт використання робота**: частка часу, коли він не вільний. |
| `robotK_empty_move` | Холостий хід до точки, де треба забрати деталь. |
| `robotK_grab` | Захоплення деталі. |
| `robotK_loaded_move` | Переїзд з деталлю. |
| `robotK_wait_slot` | Очікування з деталлю, поки на верстаті звільниться місце. |
| `robotK_release` | Вивільнення деталі. |
| `robotK_jobs_route1/2/3` | Скільки перевезень робот виконав на шляхах A→M1, M1→M2, M2→W за період T. У варіанті 1 ненульове лише для «свого» шляху. |
| `robots_util_mean` | Середній коефіцієнт використання роботів. |
| `empty_route1/2/3_mean` | Середній холостий хід робота, с, на одне перевезення шляху A→M1, M1→M2, M2→W (від точки, де робот стояв, до точки завантаження). У варіанті 1 дорівнює 6, 7, 5 с. |

`robotK_util = empty_move + grab + loaded_move + wait_slot + release`.

## Структура

```
src/fms/
  rng.py        генератори: exp = −m·ln ζ, unif(d,s), norm – полярний метод Марсальї; окремі потоки
  params.py     вхідні змінні та параметри
  elements.py   елементи мережі МО: Create, Queue, Machine, Transport (роботи), Warehouse
  model.py      алгоритм імітації, диспетчер роботів, збір статистики
  cli.py        командний інтерфейс
  report_plots.py  рисунки для пояснювальної записки
  experiments/  verification, warmup, replications, compare, capacity, distribution, improvement
tests/          перевірки коректності алгоритму
```

## Відповідність формалізму

| Об'єкт системи | Елемент мережі МО |
|---|---|
| надходження деталей exp(40) | зовнішнє надходження `Create` |
| місце зберігання на ділянці прибуття | необмежена черга `Queue` (фіксується максимум) |
| верстат 1 / 2 (до 3 деталей) | 3-канальна СМО без черги `Machine`; канал після обробки **блокований**, доки деталь не захопить робот |
| роботи | СМО транспортування `Transport`: варіант 1 – три 1-канальні СМО (кожна свій маршрут), варіант 2 – одна 3-канальна СМО з вибором найближчого каналу |
| склад | вихід з мережі `Warehouse` |
| «на верстаті немає місця», «робот зайнятий» | блокування маршрутів B(S,t) (опис у [схеми/](схеми/)) |

Обслуговування роботом складається з фаз: холостий хід до точки завантаження → захоплення unif(8,1) →
хід з деталлю → [очікування місця] → вивільнення unif(8,1). Місце на верстаті-джерелі звільняється
по завершенні захоплення; обробка починається по завершенні вивільнення.

## Припущення моделі

1. Пункти розташовані на лінії A – M1 – M2 – W; відстані A–M2 = 13, M1–W = 12, A–W = 18 с.
2. Робот після вивільнення залишається в точці призначення.
3. Варіант 2: обирається пара (вільний робот, заявка) з найменшою відстанню холостого ходу; при
   рівності – маршрут ближчий до складу (M2→W, потім M1→M2, потім A→M1), далі – раніша заявка, далі – випадково.
4. Місце на верстаті займається лише при вивільненні деталі; робот з деталлю чекає біля заповненого
   верстата. Робота призначають на доставку до верстата, лише якщо туди їде не більше роботів, ніж там
   вільних місць, плюс один (u ≤ f у момент призначення). Це правило запобігає взаємному блокуванню
   роботів; у варіанті 1 воно виконується завжди, бо до верстата їздить лише один робот.
5. Час обробки на M1 – усічений нормальний закон (значення ≤ 0 відкидаються).
6. Одночасні події виконуються у випадковому порядку; завершення обслуговування – раніше за надходження.
